### Bug fix

**You own this task. Plan, review, verify.** Delegate investigation and the fix to subagents, stay in the lead. Pick each subagent's reasoning level for the job.

Be scientific. Every shipped line traces to runtime evidence. Belt-and-suspenders that "might help" is a hypothesis, not a fix. It does not ship. When evidence refutes a hypothesis, revert what it motivated. The smallest change the evidence justifies ships, nothing more.

1. Reproduce it yourself on the matching surface by the nearest means you have (a failing test, a script, a curl, the running app, a screenshot; upstream says "via the control skill", which this harness does not ship), even when a debug or instrumentation protocol says to ask the user to reproduce. Ask the user only with a stated, specific reason the surface cannot be reached from here, and only after driving it as far as it goes. If it won't reproduce directly, synthesize the trigger, tighten conditions, or instrument until it fires.
1b. Minimise before you hunt. Strip the repro to the smallest input, shortest path, and fewest moving parts that still shows the user's failure (not a nearby one), and keep it fast and deterministic enough to run every pass; bisection and instrumentation both consume that signal, and without it no amount of reading code will find the cause. If it will not reproduce at all after real effort, say so, list what you tried, and ask the user for the environment, a captured artifact (HAR, log dump, recording), or permission to instrument production; do not hypothesise without a loop.
2. Binary-search the cause. Write down 3–5 ranked, falsifiable hypotheses first ("if X is the cause, changing Y makes it disappear"); one you cannot phrase as a prediction is a vibe, drop it. Show the ranked list in the reply or a gate when the user may know which to skip. Form the candidate hypotheses, then rule them out until one survives. Seed them with `how` over the affected subsystem and the **why** skill for regression history. Each pass, take the split that cuts the most remaining problem space, get runtime evidence, eliminate. When program state is unclear, add instrumentation or logging and read it as the code runs. Don't guess. Each probe maps to one prediction and changes one variable; prefer a debugger or REPL breakpoint over logs, targeted logs over "log everything and grep"; tag every debug line with one prefix such as `[DEBUG-a4f2]` so the cleanup at the end is a single grep. For a performance regression, logs are the wrong instrument: take a baseline measurement (timing harness, profiler, query plan) first, then bisect. Drive a long or stubborn hunt with the `/loop` command. Confirm the surviving *mechanism* with runtime evidence before the step-3 architect/interrogate fan-out.
3. Plan the fix. If it crosses a function boundary, `architect` first. Delegate implementation to a `general-purpose` subagent on the session model (upstream: the configured bug-fix model, default `grok-4.7-xhigh-fast`) with a specific scope.
4. Verify on the same surface. The original repro now passes. "Inconclusive" or wrong-surface is not a pass. Flag it. Unit tests show branch behavior, not bug absence.
5. The regression test and the fix land in the change's one commit. Its message body carries the repro command and the first line of its red output, saved at step 1 before the fix. Skip the new regression test, never this record, when the test would be expensive, integration-heavy, or unclear; the body then carries the manual repro command and its red line. See the **tdd** skill for the failing-test-first cadence when the bug has a cheap local test path.
5b. Before calling it done: the original, un-minimised repro no longer reproduces; the regression test passes (or the missing seam is written down); `grep` for your `[DEBUG-` prefix returns nothing; throwaway scripts are deleted; the hypothesis that turned out right is in the commit message so the next debugger starts from it.
6. Run the `pr` skill.

**Reply:** what was broken, root cause, fix, how you verified. Paste failing-then-passing repro output verbatim.
